6. Zoho CRM — invoices and receipts

We will connect website payments to Zoho CRM so invoice and receipt details added on the site show on the student record in CRM.

6.1 CRM setup we will do

  • Connect Zoho CRM with OAuth (same approach as Zoho Meeting).
  • Add CRM credentials in Admin settings.
  • Use Contact = student.
  • Use Deal / Enrolment = course + fee package.
  • Use Invoice record = website INV-######.
  • Use Receipt / Payment record = website RC-######.
  • Add CRM fields: Website Invoice ID, Website Receipt ID, Installment No, Balance Due, Package Name, Gateway.

6.2 Data we will send from the site

  • Student: name, email, phone, address.
  • Invoice: INV number, course, package, currency, total, installment plan, status, created date.
  • Installment: n of N, due date, remaining amount, payment method (Noon, RAKBANK, etc.).
  • Receipt: RC number, linked INV, paid amount, paid date, balance after payment.

6.3 Matching we will apply

  • Find CRM Contact by student email; create Contact if not found.
  • One CRM invoice per website payment (INV-######). Update, do not duplicate.
  • One CRM receipt per paid installment (RC-######).

6.4 When we will push to CRM

  • Admin creates invoice on the site → Contact + Deal + Invoice created/updated in CRM.
  • Student pays (gateway or manual paid) → Receipt created; invoice status and balance updated.
  • Partial pay → CRM status Partial.
  • Full pay → CRM status Paid.
  • Invoice cancelled on site → CRM status updated (kept for audit).
  • Nightly retry for any failed push.
  • One-time backfill of existing invoices and receipts.

6.5 What staff will see in CRM

  • Contact: student details, invoice list, receipt list, outstanding balance.
  • Deal: course, package, INV number, total vs paid vs due, next due date.
  • Invoice: same commercial details as the website invoice.
  • Receipt: RC number, linked INV, paid amount, paid date, gateway.
  • PDF of invoice/receipt attached on the CRM record.

11. FEE UPDATE IN PAGE

We will add fee structure and package items on a CMS Page without creating or linking a Course. Fees will be built by service, then category, then fee structure.

11.1 Structure we will use

LevelWhat it is
PageAny published website page (no Course).
Service 1 NameFirst service on the page (example: Student Visa, Attestation).
  Category 1Fee structure under Service 1 (packages, prices, include items, Enroll).
  Category 2Another fee structure under the same Service 1.
Service 2 NameSecond service on the same page.
  Category 1Fee structure under Service 2.
  Category 2Another fee structure under Service 2.

11.2 What we will build in Admin

  • Add a FEE UPDATE IN PAGE block on the Page editor.
  • Add / edit / delete Services (service name, order, show/hide).
  • Under each service, add / edit / delete Categories (category name, order, show/hide).
  • Under each category, add the Fee Structure: package name, currency, price, tax, discount, short description, key points, include items, installments, show on website.
  • Support any number of services and any number of categories per service.
  • Duplicate a service or a category (with its fee packages) inside the same page.

11.3 What the public page will show

  • Heading: FEE UPDATE IN PAGE (or the page’s own fee heading if set).
  • Service 1 Name, then Category 1 fee cards, then Category 2 fee cards.
  • Service 2 Name, then its Category 1 and Category 2 fee cards.
  • Each card: price, include items, and Enroll (same style as course fee cards).

11.4 Checkout and invoice (no Course)

  • Enroll from a page package without a Course.
  • Invoice and receipt store page, service, category, and package (course stays empty).
  • Admin Create Invoice can pick a page service/category package, not only a course package.

12. RATE AND REVIEW — instructor rating from students

We will add a Rate and Review flow so students can rate the instructor. The instructor’s overall rating is built from those student ratings.

12.1 Flow we will build

StepWhat happens
1. Eligible studentStudent is assigned to the instructor (class / folder / batch). Only those students can rate that instructor.
2. RateStudent opens Rate and Review, chooses 1–5 stars for the instructor.
3. ReviewStudent can add a written review (optional or required by Admin setting).
4. SubmitOne rating per student per instructor per batch (student can edit until Admin locks it).
5. AverageSystem calculates the instructor rating from all submitted student stars (average, count of reviews).
6. ShowInstructor sees own score. Admin / Head of Faculty see all ratings. Public instructor page can show the average if Admin publishes it.

12.2 What students will do

  • Student portal: Rate and Review on the assigned instructor (after class / access is active).
  • Give a star rating (1–5).
  • Write a short review (teaching, clarity, support).
  • See that their rating was saved. One review per instructor per batch.

12.3 What the instructor rating will be

  • Instructor rating = average of student star ratings.
  • Show number of student reviews (for example 4.6 from 18 students).
  • Instructor can read reviews of themselves (Admin can hide student names if needed).
  • Instructor cannot change student ratings.

12.4 What Admin will do

  • See all instructor ratings and reviews in Admin (filter by instructor, batch, date).
  • Publish or hide a review on the public instructor page.
  • Remove a review if it breaks policy.
  • Turn Rate and Review on or off per batch / folder.
